# 紹介動画 構成台本（3分以内）

YouTube に公開し、URLを最終レポートと発表スライドに記載する。

**録画は画面収録のみで足りる。** 顔出しは不要。
音声ナレーションが難しい場合は字幕（テロップ）でも成立する構成にしてある。

---

## 全体の時間配分（合計 2分50秒）

| # | 場面 | 長さ | 累計 |
|---:|---|---:|---:|
| 1 | 課題の提示 | 0:25 | 0:25 |
| 2 | 月次では見えない、日別では違反 | 0:30 | 0:55 |
| 3 | 希望入力 → 自動生成 | 0:40 | 1:35 |
| 4 | 違反の可視化と確定の抑止 | 0:35 | 2:10 |
| 5 | 勤務形態一覧表の出力 | 0:25 | 2:35 |
| 6 | 稼働環境とまとめ | 0:15 | 2:50 |

**最初の25秒で「何の損失を防ぐのか」を言い切ること。**
そこで興味を失われると、以降の機能説明は見てもらえない。

## 場面1　課題の提示（0:00 - 0:25）

**画面**　スライド2（解決する課題）を全画面表示

**ナレーション（または字幕）**

> 介護保険法の人員配置基準を満たさないと、
> 介護報酬は基本報酬の30パーセントが減算されます。
> しかも減算は利用者全員に、欠如が解消されるまで続きます。
> 月商800万円の事業所で2か月続けば、逸失収益は480万円。
> この多くは、シフトを組む段階で気づけていれば防げるものです。

**押さえる点**　数字は「30パーセント」と「480万円」の2つだけ。
細かい制度説明はしない。

## 場面2　月次では見えない（0:25 - 0:55）

**画面**　スライド3（なぜ現場は気づけないのか）

**ナレーション**

> 現場が使っている勤務形態一覧表は、月ごとの集計です。
> こちらをご覧ください。4職種すべてが基準を満たしています。
> ところが同じ月を日別に見ると、8件の違反が出ています。
> 機能訓練指導員が2名しかいないため、両名が休む日に配置が0になるのです。
> 月次集計だけを見ていると「適合」に見えてしまう。
> この乖離を可視化することが、このサービスの中核です。

**押さえる点**　「同じ月・同じデータ」であることを強調する。

## 場面3　希望入力から自動生成（0:55 - 1:35）

**画面**　実際のブラウザ操作を収録

**操作の手順**

1. 希望シフト画面をスマートフォン幅で表示し、
   数日ぶんの希望休を登録する（htmxで行だけが更新されるのが分かる）
2. 管理者としてシフト表画面へ移動
3. 平均利用者数に `22` を入力し、「シフトを再生成」を押す
4. **求解にかかる秒数が画面右上に出るので、そこで一拍置く**

**ナレーション**

> 職員はスマートフォンから希望休を登録します。
> 管理者は平均利用者数を入れて、生成を押すだけです。
> 人員配置基準、労働基準法の上限、就業規則、職員の希望を
> すべて同時に満たす組合せを、Google OR-Tools の
> CP-SAT ソルバーが数秒で探索します。
> 生成AIは使っていません。制約を満たすことを
> 数学的に保証できるソルバーで解いています。

**押さえる点**　求解時間が画面に出るので、実測値をそのまま見せる。
「数秒で」と言った直後に実際の秒数が映るのが効果的。

---

## 場面4　違反の可視化（1:35 - 2:10）

**画面**　シフト表画面。違反がある月を表示

**操作の手順**

1. 最下段の常勤換算の行までスクロールし、赤いセルを指す
2. 画面を横にスクロールし、職員名と日付が固定されたままなのを見せる
3. 違反一覧まで下げ、日付・職種・不足数を見せる
4. **「確定して公開」ボタンにカーソルを合わせ、押せないことを見せる**

**ナレーション**

> 基準を下回る日は赤で表示されます。
> 必要1.0に対して実際0.5、生活相談員が不足しています。
> 下の一覧では、日付・職種・不足数と対応の目安が確認できます。
> そして違反が1件でもあると、確定ボタンは押せません。
> この判定はデータベース側の条件として書いてあります。
> 減算リスクを抱えたシフトを職員に配ってしまう事故を、
> 画面の構造で防いでいます。

**押さえる点**　**押せないボタンを見せる場面が、この動画で最も重要。**
「防ぐ仕組み」であることが一目で伝わる。

## 場面5　勤務形態一覧表の出力（2:10 - 2:35）

**画面**　出力ボタン → ダウンロード → Excelで開く

**操作の手順**

1. 「勤務形態一覧表を出力」を押す
2. ダウンロードされた xlsx を開く
3. 兼務者の行が職種ごとに分かれ、按分されているのを見せる
4. **合計セルをクリックし、数式バーに `=ROUND(SUM(...))` が出るのを見せる**
5. 「日別の基準判定」シートに切り替え、○×の行を見せる

**ナレーション**

> 実地指導に提出する勤務形態一覧表を、そのまま出力できます。
> 管理者が生活相談員を50パーセント兼務している場合は、
> 職種ごとに行を分けて按分します。
> 合計と常勤換算は数式で書いてあるので、
> 運営指導の場で担当者がその場で検算できます。

**押さえる点**　数式バーを見せるのが効く。「値を貼っただけではない」証明になる。

## 収録の実務

### 録画

| 項目 | 推奨 |
|---|---|
| 解像度 | 1920×1080 |
| ツール | macOS の画面収録（⇧⌘5）で足りる |
| ブラウザ | 拡張機能を無効にし、ブックマークバーを隠す |
| 表示倍率 | 110〜125パーセント。文字が小さいと動画では読めない |

### 撮る前に必ず確認すること

- **アドレスバーにパブリックIPが写る状態にしておく。**
  ローカルで動かしただけという疑いを先に潰せる
- ブラウザのタブは1枚だけにする
- 個人情報に見える文字列を画面に出さない（デモデータは架空の氏名）
- 通知を切る

### 編集

- カット編集のみで足りる。凝った演出は不要
- 待ち時間（求解の数秒、ビルド時間）はカットせず**そのまま見せる**。
  速く見せようとして早送りすると、かえって疑われる
- テロップは場面ごとに1〜2行。読み切れる分量にする

### 公開

- YouTube に **限定公開** で上げる。URLを知っている人だけが見られる
- タイトル: `CareShift Guard — 介護事業所向け 人員配置基準チェック内蔵 シフト自動作成クラウド`
- 説明欄にGitHubリポジトリのURLを記載する

### 公開後の作業

URLが確定したら、次のコマンドでスライドに反映する。

```bash
PV_URL="https://youtu.be/xxxxxxxx" \
DEMO_URL="http://<パブリックIP>:8080/" \
  node scripts/build_slides.js
```

README の「紹介動画」「デモ環境」の行も同じ値に更新する。

## よくある失敗

| 失敗 | 対処 |
|---|---|
| 前置きが長く、1分たっても機能が出てこない | 場面1を25秒で終える。制度の詳細は語らない |
| 画面の文字が小さくて読めない | 表示倍率を上げる。撮影後にスマホで再生して確認する |
| 「押せないボタン」を見せ忘れる | 場面4の最重要点。チェックリストに入れる |
| 3分を超える | 場面3と5を削る。場面2と4は削らない |
